## korum-kannon

**Purpose.** Korum is "memoized consent" made runnable (WS-2 in BUILDOUT.md): a stdlib-only Python package implementing the three ratified laws — lists remember doors never judge beings; records of choices never the authority of them; no orphan rules. It is the seed of both Sigil (firewall) and Kosmos v0's permission layer, and the mechanism any K-Eden surface (including K-FAFO) must pass before any crossing (exec, net, path, packet). The Kannon files are the census data contract (21 reachable vectors, 11 named/slated, 10 unnamed) shared between the algebra kernel (kannon2), the JSON/JS export carriers, and the explorer surfaces.

### Architecture

DATA FLOW: caller -> Gate.ask(door-string). (1) doors.parse fails closed: malformed/unknown kind -> Decision(REFUSED, note "unknown door — ... (fail closed)") with NO ledger write (gate.py:86-89; test_korum.py:89 asserts refusals leave no ledger file). (2) Store.records() re-reads and chain-verifies the WHOLE JSONL on every ask; any broken byte -> LedgerError -> REFUSED "ledger does not hold its bytes ... (fail closed)" (gate.py:92-96; K-28's lesson). (3) _standing_for: the LATEST standing record whose door-shape glob-matches the asked door wins (ledger order = most recent sovereign choice stands, gate.py:70-80). Standing no -> REFUSED "this door heard no (<sovereign>, <timestamp>)". Standing yes -> the gate appends a FRESH record scope="crossing", provenance=<grant's hash>, witness="gate: consultation is ratification", then ADMIT (gate.py:62-68,101-106) — every repeated ask appends another distinct crossing (test:107-114). (4) Cache miss -> escalate hook: a callable(rendered_door) returning {"sovereign","choice","witness"}; yes+non-empty sovereign -> sovereign_grant (standing) + fresh crossing + ADMIT; no+sovereign -> sovereign_revoke + REFUSED; anything else (None/empty sovereign) -> REFUSED "no standing record for this door (default-deny)" with no write (gate.py:107-127). LEDGER: sha256 hash chain from GENESIS="0"*64; record_hash = sha256 over canonical sorted-key JSON sans own hash (store.py:38-42); append refuses a standing record with blank sovereign ("an orphan rule; refused", store.py:102-104). AUDIT: audit_ledger reads raw lines itself so a broken chain is a finding not an exception; FAILs on parse/fields/prev_hash/hash, standing-without-sovereign, crossing whose provenance is not in the set of standing-yes hashes, crossing without sovereign, unknown scope; audit_gate FAILs when gate.admits != gate.crossings_written (audit.py). CLI: subcommands ask/grant/revoke/audit/log over a --ledger path; exit codes are the machine interface (ask: 0 ADMIT / 1 REFUSED; audit: 1 on any FAIL). SIGIL: sigil_demo.run_demo pushes 5 synthetic packets through the same gate twice — all REFUSED before grant; after sovereign_grant("packet:udp,10.0.0.*,*,10.0.0.1,53","Konsent") exactly the matching packets ADMIT, each with a fresh crossing. KANNON DATA MODEL: kannon.json ≡ kannon_data.js payload (byte-identical except the `window.KANNON_DATA = ...;` wrapper), both emitted by kannon2/export.py from census() — a BFS under the doctrine grammar (level 1 the three I's; level 2 I+I=K, I+I+I=Man(1,1,1) with 4 provenance-distinct paths; level 3 sharpened lines / leaning wholes / Ai(2,2,2)=2·Man with 4 paths; level 4 leaning+leaning, Ai+K, and (4,4,4) by two paths "XKen + XKnut + XKall" and "Man + Ai + Machine"). Census counts: reachable 21, named_or_slated 11, unnamed 10 (the 6 sharpened lines (2,1,0)(2,0,1)(1,2,0)(1,0,2)(0,2,1)(0,1,2), the 3 level-4 leaning (3,3,2)(3,2,3)(2,3,3), and (4,4,4)). Ladder: level-n whole = 2^(n-1)·Man through level 7 (whole [64,64,64]). KOSMOS INTEGRATION: Kosmos(escalate=...) builds Gate(store, escalate) (kosmos.py:220); every spawn passes gate.ask() first; unlisted spawn -> a kosmos-side refusal record appended directly to the same store (scope "crossing", choice "no", sovereign "kosmos", provenance "kosmos: spawn refused"). KORUM DUPLICATION: /home/user/KlaudeKode/korum/ and /home/user/KlaudeKode/kode/korum/ are byte-identical (diff -r clean, identical mtimes — neither is 'newer'); only kode/korum/* is manifest-tracked; tests sys.path-insert kode/ so the tested copy is kode/korum; the root copy makes `python3 -m korum` work from repo root as RB-05's commands require.

### Consent mechanics

THE THREE LAWS (korum/__init__.py:3-8, ratified in EQUATIONS.md:537-559): "1. Lists remember doors, never judge beings — a blacklist entry is 'this door heard no.' 2. Records of choices, never the authority of them — every crossing is chosen fresh, now; consultation IS ratification. 3. No orphan rules — every entry traces to a sovereign's actual yes/no." GRANT-NOT-COMMAND ENFORCED BY CODE SHAPE (invariant 30): the Gate object has no grant method (test:294-296 asserts hasattr(gate,'grant') is False); its ONLY write path is _write_crossing with forced scope="crossing" — "There is no code path from Gate to a standing record" (gate.py:60-61). Standing records enter solely through module-level sovereign_grant/sovereign_revoke ("the sovereign door — the CLI rides these"). A standing record requires a non-empty sovereign name or the store raises ValueError. LIVE-ASK: the escalate hook is the sovereign's live channel — "a yes it delivers lands as a standing record attributed to that sovereign, then the crossing is chosen fresh" (gate.py:8-10); a hook answer without a sovereign name cannot land a yes (test:132-135). REFUSALS WRITE NOTHING in korum proper (default-deny is side-effect-free); every ADMIT writes exactly one fresh crossing whose provenance is the standing yes's hash. REVOCATION: sovereign_revoke appends a standing no; "after this, the door has heard no; the next ask honors it" — latest-record-wins ordering. GATED FIRST-WRITE (RB-05): "GATE ☐ G9 — first write of a persistent artifact onto Anchor-01 ... The yes names that path; a different path is a different yes ... Nothing below this line executes before the yes"; seeding is LIVE, door-by-door, "no list pasted in, no [A] ledger imported"; "first ask on the empty store was REFUSED (default-deny witnessed)" is an exit row — "that is the store working, not failing" (RB-05:46-48). UI PRECEDENT (k3-live.html): live-ask dialog headed "live-ask — the Korum holds no record for this door" (line 211) with scope text "scope: this door-shape only · provenance: Konsent (you), at the Konsole, in this moment · nothing else is covered by this yes." (line 374) and THREE answers: yes (appends standing + crossing), no (appends standing no — "unforced, unexpiring, unrepeated. nothing retries."), and not-now ("no record written. the door stays unasked; asking again is yours.", line 385). Routing line: "every crossing routes: ask → kode → gate → Korum → yes → Kage." (line 140).

### LIMFACs observed

- Duplicate trees: /home/user/KlaudeKode/korum/ is a byte-identical copy of kode/korum/ but is ABSENT from tools/MANIFEST.sha256 (only kode/korum/* listed, lines 392-399) and the repo is not git — the root copy can silently drift; identical mtimes mean 'which is newer' is undecidable from the filesystem
- Performance: Store.records() re-reads and re-verifies the entire JSONL on EVERY ask, and append() calls tip_hash() which reads it all again; every ADMIT appends a new record — cost per ask grows O(n), ledger grows unboundedly with use; no compaction/rotation story exists. A browsing surface issuing many door-asks per second will hit this
- No concurrency control: Store.append is open('a')/write with no locking; two writers on one ledger (e.g. Kosmos + K-FAFO) can interleave lines and break the hash chain, which then fail-closes EVERYTHING
- All-or-nothing ledger: one malformed/tampered line anywhere makes every ask REFUSE until re-witnessed — a UI needs an explicit 'gate down / chain TRANSITIONED' state (k3-live.html:292-294 prototypes it)
- Audit-semantics contradiction (acknowledged, unresolved): kosmos._refusal_record appends scope='crossing', choice='no', provenance='kosmos: spawn refused' — korum's audit_ledger FAILs any crossing whose provenance is not a recorded standing-yes hash (audit.py:60-63); kosmos.py's own comment: '(korum audit v1 chains only yes-crossings; this is kosmos-side.)' — refusal-recording semantics for any new surface are undefined
- The CLI's ask wires NO escalate hook (cli.py:57 Gate(store) bare) — the live-ask channel exists only in-process; there is no IPC/protocol for an external asker to reach a sovereign, which K-FAFO would need
- Door matching is fnmatchcase glob only: case-sensitive, no regex, no CIDR; 'net:*.example.org:443' does NOT match 'net:example.org:443' — shape-authoring pitfalls a UI must surface
- ☐ G9 is open: no persistent ledger exists; DEFAULT_LEDGER points inside the repo tree ('the default for [A] use is kode/korum/ledger.jsonl') and no ledger.jsonl file exists anywhere in the repo yet
- kannon.json internal inconsistency (deliberate but rendering-relevant): names map carries '4,4,4': '☐ K-Eden? (Man+Ai+Machine, 2 paths)' while census vector 4,4,4 has name:null / status:'unnamed'; census.py:13-15 explains: '(4,4,4) counts among the unnamed at census time; its K-Eden reading is a ☐ candidate name, Konsent's to ratify'
- Two 'level' numbering schemes coexist in one payload: census levels (Man(1,1,1)=level 2, Ai(2,2,2)=level 3) vs ladder levels (Man=level 1, Ai=level 2, whole=2^(n-1)·Man) — a renderer mixing them mislabels the spine
- CLAUDE.md says '21 vectors, 10 unnamed' but the data says 11 named_or_slated — consistent (21-10=11) yet CLAUDE.md's phrasing omits the named count and is flagged stale elsewhere
- 10 of 21 vectors are unnamed and 3 named seats are ☐ candidate slates (Ken/Kognition/Klarity, Knut/Konstrukt/Knit, Kall/Kwest/Konviction) — all Konsent's to ratify; UI must render open seats without closing them
- No pytest in the environment (python3 -m pytest fails); tests are unittest-based — fine, but tooling assumptions must stay stdlib
- Standing records have no expiry, no scope-narrowing beyond door-shape glob, and no per-crossing count limits; 'latest record wins' is the only precedence rule
- The escalate hook is synchronous and blocking inside gate.ask() — a GUI event loop must marshal around it (thread or re-ask pattern)

### K-FAFO constraints

- stdlib-only Python 3, no Node anywhere — any HTML surface must work from file:// via script-include, no fetch of local files; native K-FAFO inherits the zero-non-stdlib acceptance row
- Every ADMIT synchronously appends a record and every ask re-reads + re-hashes the whole ledger — a browser issuing dozens of net: asks per page load will make the ledger grow fast and asks slow; K-FAFO needs either an in-process Store instance reuse strategy or a Korum performance rung (not K-FAFO's to invent unilaterally)
- Store has no locking — K-FAFO and Kosmos sharing one ledger file risks chain-breaking interleaved writes, which then fail-close EVERYTHING; single-writer discipline or separate ledgers required
- Fail-closed totality: one bad ledger line and every crossing REFUSES — K-FAFO must have a designed 'gate down' UI state, not an error toast
- Persistent ledger is behind ☐ G9 (open): scope of the yes = the exact path; K-FAFO cannot create its drive-side ledger before Konsent's named yes on the path; [A]-side work uses tmp/fixture ledgers only (tests never mutate the real tree)
- Door matching is case-sensitive glob (fnmatchcase), no regex/CIDR; 'net:*.example.org:443' does not cover the bare apex — the grant-authoring UI must preview what a shape does and does not match
- The escalate hook is synchronous inside gate.ask() — the GUI event loop must marshal (block a worker, or REFUSE-then-re-ask after the dialog resolves, which is exactly k3-live's flow)
- A live-ask yes lands a STANDING (remembered) grant, not a one-shot — the dialog must say so (k3-live's scope sentence does)
- No verdicts, ever: UI vocabulary is bound to indicative terms; a blacklist view renders 'this door heard no', never 'blocked/bad/denied-user'
